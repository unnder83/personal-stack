# M5 CI/CD（GHCR 镜像 + 自托管 Runner + 自动部署与回滚） 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** push 到 `main` 后：云端构建镜像推 GHCR → VM 上的自托管 Runner 拉取并自动部署 → 健康检查失败自动回滚。

**Architecture:** 两条工作流：`release.yml`（GitHub 云端 runner：构建 api/web 镜像并推 `ghcr.io`，打 `sha` 与 `latest` 标签）与 `deploy.yml`（VM 自托管 runner：**不使用任何 `uses:` 步骤**，通过 `api.github.com` 下载该 commit 的 tarball，调用仓库内 `deploy-release.sh` 完成拉镜像、迁移、切 `current`、`up -d`、健康检查与失败回滚）。

**Tech Stack:** GitHub Actions（云端 + 自托管）、GHCR、Docker Compose、既有部署脚本实践。

**Spec:** `docs/superpowers/specs/2026-09-19-personal-stack-design.md`（§10 CI/CD、§14 网络约束与兜底）

## Global Constraints

- **网络约束**（实测）：`github.com` HTTPS 与 git clone 不可达；`api.github.com`、`codeload.github.com`、`ghcr.io`、`pipelines/broker/results-receiver.actions.githubusercontent.com`、`objects.githubusercontent.com` 可达。所有 VM 侧流程不得依赖 `github.com`。
- 生产 compose 的 `api`/`web` 改为**只引用镜像**（`${API_IMAGE}` / `${WEB_IMAGE}`），不再本地构建；镜像来自 GHCR。
- 镜像命名：`ghcr.io/unnder83/personal-stack-api`、`ghcr.io/unnder83/personal-stack-web`，标签 `<git-sha>` 与 `latest`。
- 自托管 Runner 以专用用户 `ghrunner` 运行（加入 `docker` 组），**不使用 root、不使用 sudo**；拥有 `/opt/personal-stack` 写权限；`config.sh --disableupdate` 关闭自更新（自更新走 github.com 会失败）。
- VM 侧下载 runner 安装包走 `api.github.com` 的 release asset URL（重定向到 `objects.githubusercontent.com`），不走 `github.com`。
- 部署顺序：`pull` → 迁移（一次性容器）→ 切换 `current` 符号链接 → `up -d` → 健康检查 → 失败则回滚到上一 release 并 `up -d`。
- 回滚只回滚应用与镜像，**不回滚数据库迁移**；迁移须保持向后兼容（可加列不可删列，直到新版本稳定）。
- 每个 release 目录记录 `deploy/.images`（`API_IMAGE=<tag>` / `WEB_IMAGE=<tag>`），回滚依据它恢复确切镜像。
- workflow 设置 `concurrency: deploy-production`，同一时刻只允许一个部署；同一 sha 重复部署幂等。
- 提交信息使用中文 conventional commits；开发环境与 M4 手动部署能力保持可用。

## Review Focus

1. **Runner 权限最小化**：以 `ghrunner` 非 root 运行、仅 docker 组 + 目录属主，无 sudo；runner 工作目录不可写仓库以外敏感路径。钉在 Task 3（`systemctl show` 用户、`id ghrunner` 组、无 sudoers 条目）。
2. **不依赖 github.com**：deploy 工作流无 `uses:`、tarball 走 `api.github.com`、runner 安装走 API asset URL；`curl -I https://github.com` 失败不影响流程。钉在 Task 2/4（grep 工作流无 `uses:`；安装脚本 URL 断言）。
3. **镜像可追溯与回滚**：release 内 `.images` 记录 sha 标签；回滚后 `docker ps` 显示上一 sha 镜像。钉在 Task 1/4（`test_deploy_release_records_images`、回滚后镜像断言）。
4. **健康检查失败自动回滚**：人为制造失败（发布一个把 `/api/health` 打坏或让 api 起不来的提交）→ 自动切回上一 release 且服务恢复。钉在 Task 4 的演练步骤。
5. **重复/并发安全**：同 sha 重跑不重复构建镜像（release 已存在则跳过下载）、workflow `concurrency` 防止并发部署。钉在 Task 2/4（`concurrency` 断言与幂等步骤）。

- [ ] **Step 2: 写部署脚本**

`deploy/ops/deploy-release.sh`：

```bash
#!/usr/bin/env bash
# 用法：deploy-release.sh <git-sha> [--no-rollback]
# 依赖：docker、compose v2；release 目录已由工作流解压
set -euo pipefail

SHA="${1:?用法：deploy-release.sh <git-sha>}"
NO_ROLLBACK="${2:-}"
ROOT="${ROOT:-/opt/personal-stack}"
ENV_FILE="$ROOT/.env"
RELEASE="$ROOT/releases/$SHA"

[ -d "$RELEASE" ] || { echo "release 不存在：$RELEASE" >&2; exit 1; }
[ -f "$ENV_FILE" ] || { echo "缺少 $ENV_FILE" >&2; exit 1; }

API_IMAGE="ghcr.io/unnder83/personal-stack-api:$SHA"
WEB_IMAGE="ghcr.io/unnder83/personal-stack-web:$SHA"
printf 'API_IMAGE=%s\nWEB_IMAGE=%s\n' "$API_IMAGE" "$WEB_IMAGE" > "$RELEASE/deploy/.images"

if [ -n "${GHCR_TOKEN:-}" ]; then
  echo "$GHCR_TOKEN" | docker login ghcr.io -u "${GHCR_USER:-github}" --password-stdin
fi

PROFILE_ARGS=()
if grep -qE '^CLOUDFLARE_TUNNEL_TOKEN=.+' "$ENV_FILE"; then
  PROFILE_ARGS=(--profile tunnel)
fi

compose_for() {
  local dir="$1"
  docker compose --env-file "$ENV_FILE" --env-file "$dir/deploy/.images" \
    -f "$dir/deploy/compose.yaml" "${PROFILE_ARGS[@]}" "${@:2}"
}

health_ok() {
  local dir="$1"
  for _ in $(seq 1 30); do
    if compose_for "$dir" exec -T caddy wget -qO- http://api:8000/api/health >/dev/null 2>&1; then
      return 0
    fi
    sleep 2
  done
  return 1
}

PREVIOUS="$(readlink -f "$ROOT/current" 2>/dev/null || true)"

compose_for "$RELEASE" pull
compose_for "$RELEASE" run --rm --no-deps api alembic upgrade head
compose_for "$RELEASE" run --rm --no-deps api python -m app.scripts.seed_admin

ln -sfn "$RELEASE" "$ROOT/current"
compose_for "$RELEASE" up -d

if health_ok "$RELEASE"; then
  echo "部署成功：$SHA -> $ROOT/current"
  exit 0
fi

if [ "$NO_ROLLBACK" = "--no-rollback" ] || [ -z "$PREVIOUS" ] || [ "$PREVIOUS" = "$RELEASE" ]; then
  echo "健康检查失败，未回滚（previous='$PREVIOUS'）" >&2
  exit 1
fi

echo "健康检查失败，回滚到 $PREVIOUS" >&2
ln -sfn "$PREVIOUS" "$ROOT/current"
compose_for "$PREVIOUS" up -d
if health_ok "$PREVIOUS"; then
  echo "已回滚到 $(basename "$PREVIOUS") 并恢复健康" >&2
else
  echo "回滚后仍不健康，需人工介入" >&2
fi
exit 1
```

```yaml
  push:
    branches: [main]
  workflow_dispatch:

  contents: read
  packages: write

jobs:

    runs-on: ubuntu-latest
    strategy:
      matrix:
        include:
          - name: personal-stack-api
            context: backend
          - name: personal-stack-web
            context: frontend
    steps:

      - uses: docker/setup-buildx-action@v3

          password: ${{ secrets.GITHUB_TOKEN }}

        with:
          context: ${{ matrix.context }}
          push: true
          tags: |
            ghcr.io/${{ github.repository_owner }}/${{ matrix.name }}:${{ github.sha }}
            ghcr.io/${{ github.repository_owner }}/${{ matrix.name }}:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

`deploy/ops/host/install-runner.sh`：

```bash
#!/usr/bin/env bash
# 用法：RUNNER_TOKEN=<注册token> bash install-runner.sh
# 以 root 执行（创建用户/装 systemd 服务），Runner 进程以 ghrunner 运行
set -euo pipefail

REPO_URL="https://github.com/unnder83/personal-stack"
RUNNER_HOME=/opt/actions-runner
RUNNER_USER=ghrunner
STACK_ROOT=/opt/personal-stack

command -v docker >/dev/null || { echo "需要先安装 docker" >&2; exit 1; }
[ -n "${RUNNER_TOKEN:?需要 RUNNER_TOKEN（仓库 Settings → Actions → Runners → New runner 页面获取）}" ]

id -u "$RUNNER_USER" >/dev/null 2>&1 || useradd --system --create-home --shell /bin/bash "$RUNNER_USER"
usermod -aG docker "$RUNNER_USER"

dnf install -y libicu tar >/dev/null

mkdir -p "$RUNNER_HOME"
chown "$RUNNER_USER:$RUNNER_USER" "$RUNNER_HOME"

if [ ! -f "$RUNNER_HOME/.runner" ]; then
  ASSET_ID="$(curl -fsSL -H 'Accept: application/vnd.github+json' \
    "https://api.github.com/repos/actions/runner/releases/latest" \
    | python3 -c 'import json,sys; rel=json.load(sys.stdin); print(next(a["id"] for a in rel["assets"] if a["name"].startswith("actions-runner-linux-x64-")))')"
  curl -fsSL -H 'Accept: application/octet-stream' \
    "https://api.github.com/repos/actions/runner/releases/assets/$ASSET_ID" \
    -o /tmp/actions-runner.tar.gz
  tar -xzf /tmp/actions-runner.tar.gz -C "$RUNNER_HOME"
  chown -R "$RUNNER_USER:$RUNNER_USER" "$RUNNER_HOME"
  rm -f /tmp/actions-runner.tar.gz
  runuser -u "$RUNNER_USER" -- "$RUNNER_HOME/config.sh" \
    --url "$REPO_URL" --token "$RUNNER_TOKEN" --name "vm-$(hostname -s)" \
    --labels self-hosted,linux,x64 --work "$RUNNER_HOME/_work" --unattended --disableupdate
fi

# 部署所需的最小权限：可写 release 目录、可读生产 env
chown -R "$RUNNER_USER:$RUNNER_USER" "$STACK_ROOT"
chmod 600 "$STACK_ROOT/.env"

"$RUNNER_HOME/svc.sh" install "$RUNNER_USER"
"$RUNNER_HOME/svc.sh" start
systemctl status --no-pager 'actions.runner.*' | head -5
```

- [ ] **Step 1: 写工作流（不使用任何 `uses:`）**

`.github/workflows/deploy.yml`：

```yaml
name: Deploy

on:
  workflow_run:
    workflows: [Release]
    types: [completed]
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  packages: read

concurrency:
  group: deploy-production
  cancel-in-progress: false

jobs:
  deploy:
    if: github.event_name == 'workflow_dispatch' || github.event.workflow_run.conclusion == 'success'
    runs-on: [self-hosted, linux]
    env:
      SHA: ${{ github.event.workflow_run.head_sha || github.sha }}
      GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    steps:
      - name: Download release tarball via API
        run: |
          set -euo pipefail
          mkdir -p "/opt/personal-stack/releases/$SHA"
          curl -fsSL -H "Authorization: Bearer $GH_TOKEN" \
            "https://api.github.com/repos/${{ github.repository }}/tarball/$SHA" \
            -o /tmp/release.tar.gz
          tar -xzf /tmp/release.tar.gz -C "/opt/personal-stack/releases/$SHA" --strip-components=1
          rm -f /tmp/release.tar.gz

      - name: Deploy with rollback
        run: |
          set -euo pipefail
          cd "/opt/personal-stack/releases/$SHA"
          GHCR_USER="${{ github.actor }}" GHCR_TOKEN="$GH_TOKEN" \
            bash deploy/ops/deploy-release.sh "$SHA"
```

目标形态：镜像可拉取、迁移成功、`current` 切到坏版本、`up -d` 后健康检查失败 → 自动切回上一 release 并恢复。

```bash

import pathlib
p = pathlib.Path("backend/app/main.py")
text = p.read_text()
old = '@app.get("/api/health")\nasync def health() -> dict[str, str]:\n    return {"status": "ok"}'
new = '@app.get("/api/health")\nasync def health() -> dict[str, str]:\n    raise RuntimeError("drill: forced unhealthy")'
assert old in text
p.write_text(text.replace(old, new))

git add backend/app/main.py

```

   - 工作流结论 failure（脚本回滚后仍以非 0 退出），日志含「已回滚到 … 并恢复健康」
